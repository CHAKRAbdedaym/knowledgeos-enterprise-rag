## Tools and scope

The fictional reference workstation uses a recent operating system, Git, Docker Compose, Node 22 and Python 3.12. Each project’s dependency files remain authoritative for actual versions. This document does not replace the executable KnowledgeOS README. The managed device is encrypted and locks after five minutes. Tools come from approved sources and repository access is individual. A shared developer account is prohibited even when several people are preparing the same demonstration or working through onboarding together.

## Initial setup

Clone the authorized repository, read its instructions and copy the configuration template into a local file. Set only values required for development. Secret-bearing files are excluded from Git. Local data services run in containers with named volumes. Apply migrations using the project’s documented command. Installation is complete when a useful journey works and configuration errors can be understood. Downloading dependencies alone is not evidence that the application can start, process a file or persist a query.

## Development data

Development datasets are synthetic and have a provenance manifest. Customer exports are not a shortcut for seeding. Large files and models use designated locations, outside source code where appropriate. A reset procedure clearly states what it deletes. Removing a volume is never the first response to an error without checking data value and restore options. Reproducibility includes migrations and model downloads. A successful run on one long-lived workstation cannot establish that a clean environment will behave identically.

## Contribution and diagnosis

Reproduce a problem before changing it and choose a relevant check. Use a short branch, run appropriate tests and inspect the diff. Review requests explain behavior and verification. New dependencies require justification. Do not fix certificate or permission errors by disabling protections globally. A setup report includes system, versions, command, sanitized error and expected step. The buddy helps isolate network, dependency and configuration causes. Servers are not exposed publicly for convenience; ports and allowed origins are checked before sharing.

## Applying and maintaining this guidance

Before acting, verify the scope, version and responsible role. Record an exception with its rationale, owner, expiration and next review. Report a contradiction to the document owner rather than silently combining incompatible instructions. A useful request states the expected result, observed situation and decision needed, without including secrets. Keep approved decisions in the relevant project or restricted administrative record. To revise this note, propose a reviewed change and update related references. These examples support retrieval experiments and portfolio interviews; they do not provide evidence of an actual deployment, real customer outcome or operating certification.

## Worked example

A new workstation cannot download the embedding model. The developer reports the actual network error and versions, checks the documented cache location and retries through approved means. They do not present retrieval as working until a real embedding operation succeeds.
