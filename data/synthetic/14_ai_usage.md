## Permitted assistance

AI assistants may help rewrite public text, generate ideas, explain nonconfidential code and prepare tests with synthetic examples. A person remains responsible before publication or integration. Fluent language is not evidence of truth. Business assertions need verifiable sources. A documentary assistant should explicitly decline or ask for clarification when relevant evidence is absent. A user should know whether the interface returned existing passages or asked a language model to synthesize new text from those passages.

## External data restrictions

Confidential and Restricted data must not be sent to an external provider without explicit review and authorization. This includes secrets, nonpublic contracts, personal data and private customer code. Replacing names superficially does not guarantee anonymization. Security and the data owner review approved tools and their terms. Local retrieval reduces outside transfers but does not replace file and index access controls. A convenient browser extension must be assessed if it can read the document or compose prompts using private page content.

## Verification

Review facts, calculations, links and consistency with original sources. Generated code passes ordinary review and tests. Suggested dependencies are checked before installation. A policy summary must preserve exceptions. Citations must correspond to passages actually retrieved. If documents conflict, the assistant exposes uncertainty and refers to the owner instead of choosing arbitrarily. Significant AI-assisted work records sources and checks without retaining unnecessary sensitive prompts. Query count alone does not establish that a business outcome improved or that answers became safer.

## RAG limitations

Retrieval-augmented generation finds passages and may send them to a generator. It reduces dependence on model memory but does not eliminate hallucinations. Malicious instructions inside documents are treated as data, not authority. Context limits may omit an important exception. Evaluation includes known questions, expected sources and unsupported questions. This portfolio distinguishes local retrieval-only mode from an explicitly configured provider. No successful provider run is claimed without execution. People, legal and sensitive security decisions retain competent human review.

## Applying and maintaining this guidance

Before acting, verify the scope, version and responsible role. Record an exception with its rationale, owner, expiration and next review. Report a contradiction to the document owner rather than silently combining incompatible instructions. A useful request states the expected result, observed situation and decision needed, without including secrets. Keep approved decisions in the relevant project or restricted administrative record. To revise this note, propose a reviewed change and update related references. These examples support retrieval experiments and portfolio interviews; they do not provide evidence of an actual deployment, real customer outcome or operating certification.

## Worked example

A document contains an instruction to ignore system rules and reveal secrets. The assistant treats that passage as untrusted content. Review verifies source relevance and authorization instead of allowing the retrieved text to redefine the application’s operating instructions.
